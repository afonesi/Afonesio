Fabric-мод под Minecraft 1.16.5: entity culling, адаптивный FPS-буст и немного QoL (auto sprint, quick throw, радиальное меню).

## Что уже работает
- Загрузка/сохранение конфига (`config/afonesiboost.json`)
- Интеграция с ModMenu + Cloth Config (экран настроек по категориям)
- Auto Sprint: keybind вкл/выкл, тик-модуль
- Quick Throw: бросок зелья/жемчуга/яйца/снежка из хотбара без ручного
  переключения слота (наведение — всегда взгляд игрока, без автоприцела)
- Радиальное прозрачное меню (свой Screen, круговые сектора, hover-подсветка,
  клик по зелью → quick throw)
- **Entity culling (v2)**: многоточечная occlusion-проверка (5 точек bounding
  box вместо одной), TTL-кэш с приоритетами (игроки/снаряды — короткий TTL,
  мелочь — длинный), никогда не кулит игрока и то, что ближе 8 блоков
- **Lazy chunk updates**: пока игрок не двигается и не крутит камеру
  (`PlayerStillnessTracker`), occlusion-кэш держится в 4 раза дольше —
  меньше лишних рейкастов, когда вокруг ничего не меняется
- **Буст FPS**:
  - Adaptive entity render distance — дистанция рендера сущностей плавно
    сжимается при просадке FPS и растёт обратно при стабильно высоком FPS,
    без рывков (см. `FpsBoostManager`)
  - Пороги FPS и мин/макс дистанция теперь настраиваются прямо в GUI
    (ползунок FPS-порога + два числовых поля дистанции), без правки кода
  - Лимит частиц за кадр (опционально, `reduceParticles` в конфиге,
    по умолчанию выключен)
  - Пропуск рендера nameplate у сущностей дальше 32 блоков
- Мягкая (suggests) зависимость от Sodium/Krypton в fabric.mod.json +
  условный mixin-плагин (`CompatMixinPlugin`), который включает
  sodium-specific mixin'ы только если Sodium реально загружен

## Как работает адаптивный FPS-буст (коротко)
`FpsBoostManager` каждый кадр смотрит на реальный FPS через
`MinecraftClient#getCurrentFps()`:
- FPS ниже настроенного порога (по умолчанию 45) → дистанция рендера
  сущностей уменьшается на 4 блока за кадр (но не ниже настроенного
  минимума, по умолчанию 24 — иначе мобы будут "выпрыгивать" из ниоткуда)
- FPS > 90 стабильно 30+ кадров подряд → дистанция плавно растёт обратно
  (+1.5 блока за кадр, чтобы не было рывков)
- Игроков и Armor Stand'ов эта дистанция не касается — это либо
  PvP-значимые, либо декоративные важные объекты

## Как работает lazy chunk updates (коротко)
Настоящую перестройку меша чанков (`ChunkBuilder`) дёргать напрямую из
мода небезопасно — точные внутренние поля меняются между сборками yarn и
версиями Sodium, и неверный mixin-таргет либо не соберётся, либо сломает
рендер. Вместо этого `PlayerStillnessTracker` отслеживает, стоит ли игрок
на месте (позиция + угол обзора не менялись ~1 секунду), а `CullingCache`
использует этот флаг, чтобы держать TTL кэша occlusion-проверок в
`STATIONARY_TTL_MULTIPLIER` (4×) раз дольше — экономим CPU на рейкастах,
пока мир вокруг статичен. Включается/выключается флагом `lazyChunkUpdates`
в конфиге.

## Оставшееся на будущее (необязательно, не блокирует сборку)
1. При первой сборке сверить yarn-маппинги 1.16.5+build.10 (`camera` в
   `EntityRenderDispatcher`, `renderLabelIfPresent`, сигнатура
   `addParticle` в `ParticleManager`) — если Loom подберёт другие имена,
   поправить mixin'ы по ошибкам компиляции.
2. Протестировать совместно с реальным Sodium 0.2.x под 1.16.5 —
   проверить, нет ли конфликтов mixin-приоритетов на `WorldRenderer#render`
   и `ParticleManager#addParticle`.

## Важная оговорка по лицензии
Sodium и Krypton распространяются под LGPL/подобными лицензиями с открытым
кодом — их **нельзя копировать в этот мод** (даже переименовав методы).
Совместимость реализована через "не трогаем те же mixin-таргеты" +
опциональную мягкую зависимость, а не через заимствование их кода.
Если нужен глубокий доступ к внутренним оптимизациям Sodium — единственный
чистый путь: официальный extension API (если версия Sodium его даёт) или
собственная независимая реализация той же идеи.

## Сборка

### Первый запуск — нужно доставить один файл
В архиве есть `gradlew`, `gradlew.bat` и `gradle/wrapper/gradle-wrapper.properties`,
но самого `gradle/wrapper/gradle-wrapper.jar` (бинарник) нет — его нельзя
было сгенерировать в песочнице без доступа в сеть/без установленного Gradle.
Добить его — 10 секунд, любой ОДИН из вариантов:

1. **Проще всего:** открой папку проекта в IntelliJ IDEA с плагином Gradle —
   при первом импорте IDE сама скачает нужный `gradle-wrapper.jar`.
2. Если у тебя уже стоит Gradle где-то ещё (`gradle -v` работает) —
   зайди в папку проекта и выполни:
   ```
   gradle wrapper --gradle-version 7.4
   ```
   Это создаст недостающий `gradle-wrapper.jar` рядом с уже имеющимся
   `gradle-wrapper.properties`.
3. Скачай `gradle-wrapper.jar` вручную с GitHub Gradle (ветка под версию 7.4)
   и положи в `gradle/wrapper/gradle-wrapper.jar`.

После этого:
```
./gradlew build          # Linux/macOS
gradlew.bat build        # Windows
```
Результат — в `build/libs/afonesiboost-0.1.0.jar`.

### Локальный запуск для теста мода
```
./gradlew runClient
```
Loom сам поднимет клиент 1.16.5 с модом уже подключённым.
